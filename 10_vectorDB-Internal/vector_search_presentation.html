02 · Calculate by hand

Euclidean distance

√[(qx−px)² + (qy−py)²]

A: √[(2−2)²+(4−3)²] = 1

B: √[(2−1)²+(4−2)²] = √5 ≈ 2.236

C: √[(2−0)²+(4−4)²] = 2

A → C → B

Cosine similarity

(q · p) / (‖q‖ × ‖p‖)

A: 16 / (√20 × √13) ≈ .9923

B: 10 / (√20 × √5) = 1

C: 16 / (√20 × 4) ≈ .8944

B → A → C

Explain: B is twice as far from the query as A in Euclidean terms, but B points in exactly the same direction as Q.

03 · Brute-force search in NumPy

Compare the query against every stored vector, then sort and take the first k. For 3,072-dimensional embeddings, the method stays the same.


1. Keep all vectors in a matrix: one row per stored item.
2. Compare the query vector against every row.
3. Calculate one distance or similarity score per row.
4. Sort scores and return the top K IDs. 
distances = np.sqrt(np.sum((X - q)**2, axis=1)) # Euclidean distance calculation
closest_ids = np.argsort(distances)[:k]

scores = (X @ q) / (np.linalg.norm(X, axis=1) * np.linalg.norm(q)) # Cosine similarity calculation
most_similar_ids = np.argsort(-scores)[:k]

No index: all N rows are scored for every query.

04 · Gemini Embedding 2 → Qdrant

1. Convert text to numbers

Gemini turns each sentence and the query into a high-dimensional numeric vector.

2. Search with NumPy

Score every vector with cosine and Euclidean; keep top-k as the exact reference.

3. Store in Qdrant

Create separate cosine and Euclidean collections, insert the same vectors, and run the same query.

4. Compare results

Use exact Qdrant search, compare IDs and scores, and assert they match within floating-point tolerance.

05 · Why normalization matters

Divide each vector by its length so every vector has length 1.

x̂ = x / ‖x‖
cos(q̂, x̂) = q̂ · x̂
‖q̂ − x̂‖² = 2 − 2 cos(q̂, x̂)

On normalized vectors, cosine and dot product are numerically equal. Euclidean gives the same ranking (except ties and rounding). Without normalization, raw dot product can rank short vectors very differently.

06 · What changes with HNSW?

Full scan

Compute the distance to all N vectors.

Exact · O(N × d)

No graph index required.

HNSW index(Hierarchical Navigable Small World)

Build a layered neighbor graph. Navigate promising nodes rather than examining every vector.

Approximate · often faster

Extra memory and build cost; tune recall against latency.

Benchmark both at 1,000 and 10,000 vectors in the notebook. Record measured latency and recall@10; do not assume HNSW is faster for small collections or before indexing finishes.

07 · Presentation takeaways

  1. Vectors are numerical coordinates representing items.
  2. Euclidean compares position; cosine compares direction.
  3. NumPy brute force computes scores against every item.
  4. Qdrant's exact search can reproduce NumPy results.
  5. Normalization makes cosine equal normalized dot product.
  6. HNSW speeds up many searches by skipping most comparisons, but results can be approximate.
